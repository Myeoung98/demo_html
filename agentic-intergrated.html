Auth & Headers
Tất cả request đều cần Traefik forward-auth headers. Trong môi trường dev/test, set thủ công.
Required Headers (tất cả endpoints)
x-auth-email required Email user đang đăng nhập
x-auth-user-id required User ID từ Traefik
x-auth-work-unit optional Đơn vị công tác
x-tenant-id optional Mặc định: 2122030000
Trạng thái bản ghi (business_status)
pending → activate → active → deactivate → pending
Khi tạo mới, record luôn ở pending. Sau khi activate, nội dung được ingest vào vector store (RabbitMQ). Deactivate không xóa vector store — record vẫn dùng cho lịch sử cũ.
Kiểu dữ liệu cột (data_type)
textbox Nhập text ngắn
textarea Nhập text dài
number Số nguyên/thực
email Địa chỉ email
dropdown Chọn 1 giá trị
multi_select Chọn nhiều
Response chuẩn (ApiResponse)
successbooleantrue / false
dataarrayDanh sách object kết quả
lengthintSố phần tử trong data[]
total_recordintTổng bản ghi (pagination)
errorstringThông báo lỗi khi success=false
titlesobjectMetadata bổ sung (records endpoint)
Integration Guide
Luồng tích hợp — màn hình Chi tiết danh mục
Thứ tự gọi API để render bảng dữ liệu + inline row khi người dùng nhấn "+ Thêm"
1
Load cấu trúc cột — GET /kb/categories/{category_id}/columns
Lấy danh sách KBColumnDef để biết render input / select / email cho từng cột. Kết quả này cũng nằm trong titles.columns của endpoint records nên có thể gộp 1 request.
2
Load bản ghi — GET /kb/categories/{category_id}/records
Response chứa đồng thời data[] (records) và titles.columns (column defs) — 1 request thay thế được bước 1.
3
Người dùng nhấn "+ Thêm" → render inline row rỗng
FE render dòng mới theo titles.columns: textbox/textarea → input, dropdown/multi_select → select, email → input[type=email].
4
Người dùng nhấn ✓ Lưu — POST /kb/categories/{category_id}/records
Gửi body {"data": {"tên_cột": "giá trị"}}. Record mới tạo luôn ở trạng thái pending.
5
Người dùng toggle Trạng thái → ON — PUT /kb/categories/{category_id}/records/activate
Gửi {"record_ids": ["<record_id>"]}. API tự động ingest nội dung vào vector store qua RabbitMQ. Chỉ record đang pending mới được activate.
6
Người dùng chỉnh sửa row — PUT /kb/categories/{category_id}/records/{record_id}
Có thể sửa cả record đang active hoặc pending. Trạng thái giữ nguyên sau khi sửa.

PUT /kb/categories/{category_id}/records/activate US_07_03_03
Bulk activate: chuyển từ pending → active và trigger ingest vào vector store qua RabbitMQ. Chỉ record đang pending mới được xử lý — các record khác trong list bị bỏ qua.
JSON 
{
  "record_ids": [
    "684c3d4e5f6a7b8c9d0e1f20",
    "684c3d4e5f6a7b8c9d0e1f21"
  ]
}
// Tối thiểu 1 phần tử. Toggle đơn lẻ: truyền mảng 1 phần tử.
JSON 
{
  "success": true,
  "data": [{
    "activated": 2,
    "record_ids": [
      "684c3d4e5f6a7b8c9d0e1f20",
      "684c3d4e5f6a7b8c9d0e1f21"
    ]
  }],
  "length": 1
}
Tất cả record đều đang active:
{"success": false, "error": "Không có bản ghi nào ở trạng thái Đang chờ duyệt"}
Lưu ý vector store: Sau activate, backend tự động publish message lên RabbitMQ để ingest nội dung vào vector store. FE không cần gọi thêm endpoint nào.
DELETE /kb/categories/{category_id}/records US_07_03_05
Bulk delete bản ghi — xóa vĩnh viễn khỏi MongoDB, lưu audit log. Hỗ trợ xóa đơn lẻ (mảng 1 phần tử) hoặc nhiều cùng lúc. Xóa được cả record đang pending lẫn active.

    "684c3d4e5f6a7b8c9d0e1f21",

  ]
